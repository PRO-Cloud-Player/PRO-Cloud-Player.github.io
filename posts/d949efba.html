一个小白，用 Vibecoding 给 Hexo 写了个本地管理端

发表于2026-08-26|更新于2026-08-26|随笔

写在前面

我不是专业后端工程师。平时用 Hexo 写博客，编辑文章总要在编辑器、终端、git push 之间来回切，感觉有点累。

于是我试了一条现在很流行的路：Vibecoding——用自然语言跟 AI 描述需求，让它帮我把软件一点点搭出来。最后做出了叫 Clover 的东西：一个给 Hexo 用的本地管理端，可以在窗口里写文章、定稿、一键推到 GitHub。

这篇文章不讲实现细节，只想把「为什么这么做、整体怎么跑」说清楚。

我到底想解决什么问题

Hexo 本身很轻：文章就是 Markdown，配好主题和 Actions 就能发布。痛点主要在「管理」：

  • 新建 / 改稿要自己找文件
  • 草稿和已发布文章容易混
  • 发到线上还要自己 commit、push
  • 想要像「后台」那样点几下，又不想给博客挂一个重型插件

市面上有类似 hexo-admin 的方案，我更希望做成：

  1. 独立客户端，不是塞进 Hexo 的插件
  2. 尽量不依赖本机再装一套 hexo / 复杂脚本
  3. 能在 Windows 上双击打开用

技术方案（用大白话）

一句话概括

Clover 不管「网站长什么样」，只负责管「博客仓库里的 Markdown 和 Git」。
真正生成网页、部署上线，还是交给原来的 Hexo + GitHub Actions。

可以想成：Hexo 是「印刷厂」，Clover 是「编辑部的写稿台」。

三层分工

层 干什么
界面 列表、编辑器、按钮（网页 UI；也可包进桌面窗口）
核心逻辑 读配置、建草稿、改文章、定稿、推 Git
博客仓库 你的 Hexo 目录：_posts、图片、Git 远程

核心逻辑用 Rust 写成一个库；外面挂三种入口，能力差不多：

  • 命令行（CLI）：适合偶尔敲命令
  • 浏览器后台：本机开一个小服务，浏览器里用
  • 桌面端（Tauri）：原生窗口，适合日常写稿；Windows 可打成安装包

这样做的好处是：UI 怎么换，业务规则只维护一份。

为什么不是 Hexo 插件

插件要跟着博客仓库走，还容易和 Node / Hexo 版本绑死。
Clover 是站在仓库外面的工具：你选中博客根目录（有 _config.yml 的那个），它就去读写里面的文件。

换电脑、换博客路径，只要目录选对，管的就是那一份仓库。

草稿 → 定稿 → 发布（三个词别混）

这是我自己踩坑最多、也最想写清楚的一点：

  1. 保存
    只改本地那篇 Markdown，不上 GitHub，也不等于博客已更新。

  2. 定稿到博客
    把「本地草稿」挪进博客的 source/_posts/...。
    这时文章进了博客仓库工作区，但还没 push。

  3. 一键发布
    对当前打开的博客目录做 Git 提交，并推到它的 origin。
    之后靠 GitHub Actions 跑 hexo generate 等，线上才会变。

草稿刻意不放进博客仓库，而放在软件安装目录旁的 local-drafts，免得半成品跟着 Git 满天飞；想发的时候再定稿。

日记加密也不在客户端存密码，而是约定好标签（比如「日记」），交给博客里已有的加密插件配置去处理。

发布推到哪里

很简单：推到你打开的那个博客目录所配置的远程仓库。

  • 选自己的博客 → 推自己的
  • 选别人的博客路径 → 推别人的 origin（当然要有权限）

跟「Clover 装在哪台电脑」无关，只跟「当前绑定了哪个仓库」有关。

Vibecoding 对我意味着什么

整条链路里，我大致是这样协作的：

  1. 先说清产品流程：草稿 / 定稿 / 发布不要混
  2. 让 AI 按模块长出来：读写文章、Git、界面、桌面打包
  3. 真机试用，把「拒绝访问」「下拉框不好用」「装到别的电脑路径错了」这类问题反馈回去再改
  4. 把约定写进文档，避免下次自己也忘了

作为小白，我学到的不是某句 API，而是：

  • 先想清楚状态机（草稿、已入库、已推送）再写功能
  • 一份核心逻辑 + 多种壳，比复制三套代码稳
  • 打包分发和开发机路径不是一回事，权限问题要尽早验证

Vibecoding 不会替你「想明白要什么」，但很适合在方向清楚后，把力气花在打磨体验上。

现在能做什么（功能速览）

  • 文章列表：搜索、按标签 / 分类 / 本地或已发布筛选
  • 新建 / 编辑 Markdown（带编辑器、可粘贴图片）
  • 本地草稿 → 定稿到 _posts 子目录
  • 一键查看变更并推送到 GitHub
  • CLI / 网页后台 / Windows 桌面端

站点主题、评论、CDN 那些，仍然是 Hexo 博客自己的事；Clover 只管「写」和「推」。

写在最后

如果也在用 Hexo，又懒得每次打开一堆工具：可以想想自己的工作流里，哪几步最烦，能不能收成「本地一个小客户端」。

我这条路是：不改造 Hexo，只做编辑部；印刷和上架继续交给原来的流水线。

对小白来说，这已经够当成一次完整的产品练习了——从想法、方案、联调，到装到另一台电脑还能用。

上面👆的内容为Cursor AI自动生成，这篇文档是在第二台电脑上测试的，我更想使用这个文章作为例子做一个测试，看看这个客户端能不能正常的使用。目前这个客户端功能还是很简单，不过随着以后项目慢慢跑通，会陆陆续续的添加新的功能的。
